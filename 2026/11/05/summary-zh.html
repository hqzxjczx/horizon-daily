OpenSSH 10.6p2 修复 musl libc 长密码认证绕过漏洞 ⭐️ 8.0/10

OpenSSH 10.6p2 于 11 月 5 日发布，修复 CVE 级漏洞：在使用 musl libc 且未启用 PAM 的系统上，若 /etc/shadow 中存在密码哈希为 '*' 的账户（即禁用密码登录的账户），攻击者可使用 256-1024 字节长密码绕过认证登录其他有效账户。Alpine Linux 3.16+ 已发布修复包；临时缓解措施为设置 PasswordAuthentication no。目前无在野利用报告。

hackernews · josemrb · 11月5日 12:19 · 社区讨论

「背景」 该漏洞源于 musl libc 的 crypt() 实现中对 SHA-256/512 哈希的处理缺陷，当密码哈希为 "*"（表示禁用密码登录）时，长度在 257 至 1024 字节的密码会导致 crypt() 返回 "*"，从而绕过认证。Alpine Linux 等基于 musl 的发行版受影响，问题自 2016 年起存在，OpenSSH 10.6p2 修复。

「影响与修复」 Alpine Linux 上运行 musl libc 且未启用 PAM 的 OpenSSH 部署，若存在密码哈希为 '*' 的账户（如锁定账户或仅密钥登录账户），攻击者可用 257-1024 字节任意密码绕过认证登录。受影响用户需升级至 OpenSSH 10.6p2 或应用 Alpine 3.16+ 修复包，无法立即升级者应设置 PasswordAuthentication no 禁用密码登录。

「社区讨论」 tonnydourado 指出漏洞触发条件苛刻：需 musl 编译 sshd、无 PAM、启用密码登录、至少一个 '*' 哈希账户、至少一个有效密码账户，实际风险低于标题暗示。mpyne 解释利用原理：crypt() 在特定长度下将长密码哈希结果与 '*' 相等，导致验证通过。BoppreH 归因于带内信号设计缺陷：'*' 同时用作“禁用密码”和“哈希错误”标记。amluto 补充 musl 已在 crypt_des 中修复同类问题，但遗漏了 crypt_sha256/512 路径。

ULC 音频编解码器在 N64 上实现实时 44.1kHz 立体声解码 ⭐️ 7.0/10

ULC 编解码器在 N64 的 93.75MHz MIPS CPU 上实现实时 44.1kHz 立体声解码，极少量 RAM。文章深入剖析位打包、定点运算、内存高效解码设计，适配复古/嵌入式系统。

hackernews · frostbyte7 · 11月5日 12:51 · 社区讨论

「背景」 N64 仅有 4MB RDRAM（可扩展至 8MB）和 93.75MHz MIPS CPU，音频解码需在极小内存与算力下实时运行。1990 年代末 MP3 等主流编解码器受 Fraunhofer 等专利保护，商业游戏机需支付高额授权费；Nintendo 曾两次实现 MP3 解码器并最终向 RAD Game Tools 与 Fraunhofer 付费取得专利豁免。ULC 编解码器专为该硬件约束设计，采用定点运算与紧凑位打包，避开专利风险，适合复古平台与嵌入式场景。

「影响」 为复古游戏开发者和嵌入式音频工程师提供极简高保真方案，展示在严苛硬件约束下实现 CD 质量音频的可行路径。

「社区讨论」 jonas21 指出演示音质差源于原曲而非编解码器；midnightclubbed 回顾 1999 年专利雷区导致 N64 MP3 解码器两次重写并最终授权 RAD；pona-a 表示想自写编解码器；pferdone 惊讶 Half-Life 能在 N64 运行。
