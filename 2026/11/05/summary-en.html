OpenSSH 10.6p2 fixes musl crypt() password bypass on Alpine ⭐️ 8.0/10

OpenSSH 10.6p2 released November 5 fixes a vulnerability allowing 257-1024 byte passwords to bypass SSH authentication on musl-based systems without PAM. The flaw affects Alpine Linux 3.16+ when password authentication is enabled, at least one account has '*' as password hash in /etc/shadow, and another account has a valid password. Alpine has published fixed packages; mitigation is setting PasswordAuthentication no. No exploitation reports exist yet.

hackernews · josemrb · Nov 5, 12:19 · Discussion

「Background」 Musl libc crypt() implementation uses in-band signaling where "*" indicates both "no password set" and "hashing error". This design flaw existed since 2016 in musl-based systems including Alpine Linux, OpenWRT, and buildroot with default configurations. OpenSSH 10.6p2 released November 5, 2026 fixes the bypass by adding password length validation before calling crypt(). Alpine Linux published patches for versions 3.16 and later.

「Impact」 Alpine Linux containers and VMs running OpenSSH with musl libc and password authentication enabled are vulnerable to authentication bypass via 257-1024 byte passwords when any account has '*' as password hash. Attackers with network access and valid username can log into key-only accounts. No exploitation reported yet. Fix: upgrade OpenSSH to 10.6p2 or apply Alpine security patches for 3.16+. Immediate workaround: set PasswordAuthentication no in sshd_config. Public Alpine images on container registries may be affected; verify base image patch level.

「Community discussion」 Commenters note the headline overstates severity given multiple required conditions: musl libc, no PAM, password auth enabled, '*' hash present, and valid password on another account. The root cause is in-band signaling: musl's crypt() returns '*' on hash failure, which matches the '*' sentinel used for disabled accounts in /etc/shadow. Musl previously fixed this for DES crypt but missed the SHA-256/512 code path.

DialFork Benchmarks Procedural Hallucination in Conversational Agents ⭐️ 8.0/10

DialFork introduces first benchmark measuring procedural hallucination in conversational agents. Agents execute correct tool calls but skip required dialogue steps — asking, confirming, telling results. Three tasks: turn-level drift detection (Task 3), dialogue-level procedural distance (Task 2), set-level distribution comparison (Task 1). From Idiap Research Institute with Logitech collaboration. Open data, code, predictions, human judgments. Leaderboard on Hugging Face accepts CSV submissions.

reddit · r/MachineLearning · /u/sergbur · Nov 5, 10:44

「Background」 Procedural hallucination is third evaluation axis alongside factual accuracy and correct tool use. Most dialogue steps are agent utterances, not tool calls. Prior benchmarks focus on factual correctness or tool-use accuracy, not procedural adherence. DialFork simulates dialogues where agent follows procedure, then drifts at varying points across 24, 12, and 30 dialogue variants.

「Impact」 Enables live guardrails via streaming drift detection, conversation retrieval by procedural similarity not just content, and regression monitoring after model upgrades. First standardized metric for procedural drift in LLM agents. Public leaderboard tracks progress on all three tasks.

ULC Audio Codec Enables Real-Time 44.1kHz Stereo on N64 ⭐️ 7.0/10

Article details ULC codec achieving real-time 44.1kHz stereo decoding on N64 93.75MHz MIPS with minimal RAM. Codec uses clever bit-packing and fixed-point arithmetic for memory-efficient decoding. Targets embedded and retro systems with severe hardware constraints.

hackernews · frostbyte7 · Nov 5, 12:51 · Discussion

「Background」 Nintendo 64 audio historically relied on sequenced formats (MIDI-like) due to cartridge space and CPU limits; streaming PCM or MP3 was impractical. Fraunhofer MP3 patents forced Nintendo and Rare to license decoders from RAD Game Tools even when unused, creating a patent minefield for compressed audio on the console. The ULC codec avoids patented transforms, using fixed-point arithmetic and bit-packing tailored to the 93.75 MHz MIPS R4300i and 4 MB RDRAM, enabling real-time 44.1 kHz stereo decode without licensing fees.

「Impact」 Developers gain reference implementation for ultra-low-resource audio decoding on vintage MIPS hardware. Techniques applicable to other constrained embedded platforms needing software-only audio playback.

「Community Discussion」 Commenters note original N64 MP3 decoder required patent licensing from Fraunhofer via RAD Game Tools; ULC avoids this minefield. One user confirms demo audio quality matches source track limitations. Another expresses interest in writing custom codec inspired by approach.
